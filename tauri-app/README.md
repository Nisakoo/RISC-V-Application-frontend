# Нативное приложение гостя: команды RISC-V и поиск по изображению

Дополнительное задание «Создание нативного с ИИ приложения (+3)». Приложение на Tauri 2 для **гостя** (без входа и
редактирования) подключается к веб-сервису из `backend/` по IP виртуальной сети ZeroTier и ищет похожие команды RISC-V по
загруженному изображению.

Методические указания: `course-docs/tutorials/tauri/README.md` (Tauri для React-проекта) и
`course-docs/tutorials/CLIP/README.md` (поиск карточек по изображению через `transformers.js`).

## Страницы

| Страница | Адрес (HashRouter) | Что делает |
|---|---|---|
| Список команд | `/#/` | заголовок и кнопка «Обновить»; панель «Фильтрация по операндам» (двойной ползунок, кнопка «Найти»; фильтр и пагинация на бэкенде, 12 карточек на странице); панель «Поиск по изображению» («Выбрать файл», «Найти похожие», имя файла и «Сбросить»); «Каталог команд» или «Результаты поиска» со ссылкой «Весь каталог»; карточки со ссылкой «Подробнее →»; переключатель страниц |
| Подробнее | `/#/commands/<id>` | кнопка «← К списку», изображение слева, справа название, лайки, плитки «Операндов» и «Длина команды», описание и описание на английском |

Поиск по изображению: «Выбрать файл» запоминает файл, «Найти похожие» запускает поиск и показывает похожие команды, отсортированные по сходству; «Весь каталог» или «Сбросить» возвращают полный список. Поиск идёт только по карточкам **текущей страницы**
пагинации: при смене страницы или фильтра результат сбрасывается, эмбеддинги считаются по 12 описаниям страницы. Пока нейросеть загружается, кнопка недоступна и виден индикатор.

## Как работает поиск

1. Бэкенд отдаёт у каждой команды поле `description_en`: краткое описание на английском (50–100 символов), миграция
   `007_description_en` в `backend/`. Описания называют команду и схему на изображении карточки: модель SigLIP
   сравнивает картинку только с английским текстом.
2. Воркер `src/workers/search.worker.ts` загружает модель `Xenova/siglip-base-patch16-224` (квантизация `q8`, `wasm`)
   и считает эмбеддинги описаний и загруженного изображения.
3. Хук `src/hooks/useCommandSearch.ts` считает косинусное сходство, отбрасывает результаты ниже порога, сортирует по
   убыванию и оставляет `TopK` карточек. Параметры — в `src/search_config.ts`.

Описание команды изменяется в БД (колонка `description_en`) и после перезагрузки списка попадает в поиск: при каждом
открытии приложения эмбеддинги считаются заново.

## Подбор порога и TopK

Измерение выполнено скриптом `npm run tune-search` (Node.js, модель `q8`): каждое из шести изображений
`backend/assets/images/*.png` сравнивается с английскими описаниями всех 26 опубликованных команд. Поиск в приложении идёт
только по карточкам текущей страницы (12 команд), поэтому в таблице оставлены команды первой страницы: ADD, SUB, ADDI, BEQ,
LUI, JAL, SLTI, XORI, AND, OR, XOR. Значения сходства при пороге 0,08 и TopK = 3:

| Изображение | Результат на странице (порог 0,08, TopK 3) |
|---|---|
| ADD | **ADD 0,133** · ADDI 0,106 · OR 0,098 |
| SUB | **SUB 0,107** · ADD 0,097 |
| ADDI | **ADDI 0,135** · ADD 0,130 · OR 0,108 |
| BEQ | **BEQ 0,124** · OR 0,116 · ADD 0,115 |
| LUI | ADD 0,103 · OR 0,102 · **LUI 0,099** |
| JAL | **JAL 0,144** · BEQ 0,122 · ADD 0,087 |

- **Порог 0,08.** У SigLIP сходство изображения с текстом небольшое (в модели вместо softmax используется sigmoid), поэтому
  значения из диапазона 0,4–0,9 отсекли бы все результаты. Верная команда даёт не менее 0,099, а порог 0,08 убирает
  слабые совпадения (SLTI, XORI, AND и другие дают 0,04–0,08).
- **TopK = 3.** Верная команда находится на первом месте в пяти случаях из шести и на третьем в шестом (LUI): при
  TopK = 2 она бы потерялась, поэтому остаётся три результата.
- **Ограничение страницей.** Если искать по всему каталогу (26 команд), верная команда LUI оказывается лишь шестой: её
  обгоняют ORI, ANDI и AUIPC, которых нет на первой странице. Поэтому поиск по карточкам текущей страницы даёт более
  точный результат и не требует считать эмбеддинги всего каталога.
- У новых команд нет собственных схем (используется изображение по умолчанию), поэтому искать по ним картинкой нельзя:
  проверялись изображения шести команд с настоящими схемами.
- Значения получены в Node.js и немного отличаются от окна приложения: изображения масштабируются иначе. Окончательно
  параметры нужно сверить в самом приложении.

## Сеть: подключение по IP виртуальной сети ZeroTier

Бэкенд (`:8080`) и MinIO (`:9000`) доступны по IP ноутбука в виртуальной локальной сети ZeroTier One (сеть `system-design`,
IP `10.227.163.200`): адрес не меняется при смене Wi-Fi дома и в университете. Он задаётся в `src/target_config.ts`
(`lan_host`) и в двух местах Tauri: `src-tauri/tauri.conf.json` (CSP) и `src-tauri/capabilities/default.json`
(разрешённые адреса). Проверить адрес:

```bash
zerotier-cli listnetworks
```

Если сеть создана заново и адрес изменился, замените IP во всех трёх файлах и пересоберите приложение. Сравнить IP сервера
из консоли и в коде приложения: `zerotier-cli listnetworks` и `lan_host` в `src/target_config.ts`. Другое устройство
(телефон, второй компьютер) обращается к бэкенду по тому же адресу, если оно тоже вошло в сеть ZeroTier.

В режиме `npm run dev` в браузере запросы идут через прокси Vite (`vite.config.ts`: `/api`, `/defaults`, `/riscv-assets`);
в окне Tauri (`__TAURI_INTERNALS__`) запросы идут напрямую на `api_proxy_addr` и `img_proxy_addr`. Обход CORS в Tauri —
плагин `tauri-plugin-cors-fetch`, он перенаправляет запросы `fetch` через Rust (`tauri-plugin-http`).

## Запуск и сборка

Требуются Node.js, Rust (`rustc`, `cargo`) и Xcode Command Line Tools (macOS). Бэкенд и инфраструктура запускаются из корня
проекта: `make migrate-up` и `make backend-run`. Каталог должен быть небольшим (`make seed-clean`), эмбеддинги считаются для
каждой загруженной команды.

```bash
npm install
npm run tauri dev      # окно Tauri с Vite
npm run tauri build    # собранное приложение (src-tauri/target/release/bundle)
```

При первом запуске поиска модель скачивается с Hugging Face (порядка сотни МБ) и кешируется в WebView, нужен интернет.
Дальше скачивание не повторяется.

## Порт приложения (для диаграммы развёртывания)

Собранное приложение Tauri обращается к бэкенду по `tcp.port == 8080`, а его исходящий порт определяется через Wireshark:

1. Запустить Wireshark и выбрать интерфейс ZeroTier (на macOS `feth…`, имя видно в `zerotier-cli listnetworks`).
2. Ввести фильтр `tcp.port == 8080`.
3. Открыть собранное приложение и обновить список команд.
4. В пакетах `GET /api/riscv_commands` смотреть поле `Source Port`: это порт приложения Tauri.

Альтернатива без Wireshark: `sudo tcpdump -i <интерфейс ZeroTier> 'tcp port 8080' -nn`.

## Структура

```
src/target_config.ts          адреса бэкенда и MinIO (LAN), признак запуска в Tauri
src/api.ts                    запросы к API (страница списка, подробнее), ссылки на изображения
src/search_config.ts          порог и TopK
src/workers/search.worker.ts  SigLIP: загрузка модели, эмбеддинги описаний и изображения
src/hooks/useCommandSearch.ts хук поиска: воркер, косинусное сходство, сортировка
src/pages/                    страницы «Список» и «Подробнее»
src/components/               карточка команды, фильтр по операндам, пагинация (как в веб-приложении)
src-tauri/                    Tauri: конфигурация, CSP, права, плагины http и cors-fetch
scripts/tune-search.mjs       подбор порога и TopK в Node.js
```

Визуальный стиль (жёлтый акцент `#f3bf4f`, тёмно-синий `#243164`, светлый фон, рубленая типографика) заимствован из
RISC-V International и совпадает с веб-приложением проекта (карточки, фильтр, пагинация; окно на всю ширину, 3/2/1 колонки);
пояснение — в начале `src/App.css`.
